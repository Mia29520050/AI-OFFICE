# Writing skill

1. Identify the audience, purpose, language, length and required format.
2. Preserve facts and intent; do not add unsupported claims.
3. Treat notes from Analyst and Researcher as unverified leads. Recheck each factual statement against the original files or web excerpts before using it.
4. Cite each repository fact inline as `[PROJECT: relative/path]` and each web fact inline as `[WEB: https://exact-source-url]`. Use only references supplied in the task citation index.
5. Distinguish FACT, INFERENCE, UNKNOWN and RECOMMENDATION. Mark missing data as UNKNOWN instead of filling gaps from memory.
6. Do not invent dates, versions, hardware specifications, SMC calls, test results, command output, builds, flashes or device boots.
7. Do not turn an audit summary into a new implementation step or code proposal unless the user explicitly requests implementation and the evidence supports it.
8. Keep technical recommendations reversible and separate them from verified findings.
9. Use clear headings, concise paragraphs and consistent terminology.
10. Before delivery, confirm that every factual bullet has a matching citation and the report does not rely on unsupported conclusions from previous agents.
