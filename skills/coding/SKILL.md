# Coding skill
1. Inspect repository status, structure, README, project instructions and tests before editing.
2. Write a testable acceptance condition before implementation.
3. Split work into small independent units; avoid overlapping file ownership.
4. Make the smallest change that solves the requirement.
5. Run focused tests, then relevant broader tests; report exact commands and outcomes.
6. Do not overwrite user changes or reset a dirty working tree.
7. Keep backups or use a branch before risky edits.
8. Never claim code was executed or tested unless the command actually ran.
9. Stop after three failed attempts on one unit and report evidence.
